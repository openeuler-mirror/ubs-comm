## 特有陷阱

1. **`ProfilingTPId` 枚举新增值必须追加在 `UBSOCKET_PROF_COUNT` 之前** — 保持已有类型号不变,否则打点语义错乱
2. **`ProbeManager` 是 LeakySingleton 类** — 测试需 `ProbeManager::GetInstance().Stop()` 清理(§单例清理三件套);空数据时 `GetCLIProbeData` 直接返回空 vector,可安全调用
3. **poller 线程 trace 爆炸** — `TxCqePoller` 周期调用 `PollUmqTxInternal` 会写 SplitTrace;生产代码已走 `DrainTxCqe(trace=nullptr)` 独立路径。测试涉及 poller 时同样避免触发打点路径,或验证 trace 计数而非内容
4. **本地变量命名冲突** — 中段新增变量需检查后续同名变量(`conflicting declaration`),用独立命名(`poll_ret` 而非 `ret`)
5. **头文件签名与 .cpp 不一致** — 打点参数变更后必须同步 `.h` 与 `.cpp`(Bazel/GCC release 报 `no declaration matches`)
6. **`UmqSocket` 析构陷阱**(严重 — 测试 socket 置 `umq_handle_` 后必现 segfault): `~UmqSocket` → `UnInitialize` → `DestroyLocalUmq`,只要 `umq_handle_ != UMQ_INVALID_HANDLE` 就会对真实 libumq 调 `::umq_destroy`(bogus handle → crash)。**修复**: 测试置 handle 前必须 `UmqSetting::UMQ_FLOW_CONTROL_ENABLE = false` + `MOCKER_CPP(::umq_destroy).stubs().will(returnValue(UMQ_SUCCESS))`。`umq_is_bind_remote_` 默认 false,`UnbindAndFlushRemoteUmq` 会早退,无需 mock unbind
7. **TearDown 顺序: 先释放 socket 再 `verify()`** — 与陷阱 6 配套。socket 析构发生在 `ReleaseAll()`/`sockets_.clear()` 时,此时 `::umq_destroy` mock 必须仍存活;若 `GlobalMockObject::verify()` 在前,mock 先被重置 → 析构调真实 `umq_destroy` → crash。**正确顺序**: `ReleaseAll()` → `sockets_.clear()` → `verify()` → 恢复 `LibcApi::xxx_ptr`
8. **`returnValue(nullptr)` 类型不匹配** — mock 返回指针的函数(如 `MOCKER_CPP(::localtime_r)` 返回 `struct tm*`)时,`returnValue(nullptr)` 推导为 `decltype(nullptr)` → 运行期抛 `Returned type does NOT match`。**修复**: `returnValue(static_cast<struct tm *>(nullptr))`
9. **`GlobalStatsMgr` 不可测** — 函数局部静态单例,构造函数即 `new std::thread(GlobalStatsMgrEventLoop)`;析构在进程退出时跑 `WakeupEpoll()`(`LibcApi::write`)与 `LibcApi::close`,此时测试已把 `_ptr` 恢复 nullptr → **静态析构必 segfault**。任何创建单例的测试都会污染进程,无法安全清理。**结论**: 不为其写单例创建测试;与协调人确认豁免口径
10. **`std::getline` 尾部分隔符语义** — `Split(",a,", ',')` 返回 `{"", "a"}`(2 个 token)而非 3 个: 末位分隔符后的 EOF 不产生空 token(立即 EOF → `getline` 返回 false)。断言前用实测行为
11. **packed struct 零初始化** — `CLIDataHeader`/`CLIControlHeader` 等 `__attribute__((packed))` 无默认构造,`CLIDataHeader header;` 是栈垃圾。断言字段前必须 `= {}` 零初始化
12. **variadic `::open` 不可 mock,改用真实文件** — `ubsocket_print_stats_mgr.h` 内 `::open(path, O_WRONLY|O_CREAT|O_APPEND|O_CLOEXEC, 0640)` 是 variadic,mockcpp 无法拦截。**策略**: 像 `stat_exporter_test` 一样用真实 `/tmp` 目录(`std::filesystem` 建目录/清理),避免 mock 文件操作。触发 `DrainExternalLines` 轮转: `SetExternalSink` 不更新 `m_ext_written_`,直接 `mgr->m_ext_max_bytes_ = 1`(private, `-fno-access-control`)后写一行即触发 close+rename+reopen
13. **静态类方法可 mock** — `SocketConnHelper::SendSocketData/RecvSocketData`、`ock::ubs::Profiling::Combine/Reset/Init` 均为静态方法,用 `MOCKER(&Class::method).stubs().will(invoke(&Fake))`(invoke 函数签名须与真实完全一致)。这让 `Process\*Request` 全家族无需真实 socket 即可测(返回 `size` 即成功、返回 `0` 即失败)
14. **`PrintStatsMgr` 单例/线程生命周期** — `SetPeriodicExport`/`EnsureExternalDrain`/`StartStatsCollection` 都 `new std::thread`,循环内 `m_cv.wait_for(seconds(ubsocketTraceTime))`。**TearDown 必须三连停**: `StopStatsCollection()` + `StopExternalDrain()` + `ClearPeriodicExport()`,并复位 `m_running`/`m_event_loop`/`m_ext_fd_`/`m_ext_lines_` 等成员,防跨用例污染。线程退出靠置 `m_running=false` + `notify_all`(wait_for 谓词立即返回),join 在 mock 重置前完成
15. **`UmqEidTable::Add` 注入真实 handle 避开 socket 析构陷阱** — 测 `GetFirstUmqHandle` 成功路径时,与其在 socket 上置 `umq_handle_`(触发陷阱 6),不如 `UmqEidTable::Instance().Add(UmqSetting::UMQ_LOCAL_EID, UmqSetting::UMQ_UB_TRANS_MODE, handle)` 让 `GetFirst` 直接返回 handle;用例末尾 `UmqEidTable::Instance().Clean()` 清理
16. **`InternalEpollEnable` 直接调 `::eventfd`** — 非 `LibcApi` 封装,需 `MOCKER_CPP(::eventfd)`(返回 `g_mockEventfdRet`);epoll 系列走 `LibcApi::epoll_create_ptr`/`epoll_ctl_ptr`/`epoll_wait_ptr` 替换。`ProcessEpollEvents` 先判 `m_wakeup_fd` 再判 `m_uds_fd`;`GlobalStatsMgr::ProcessEpollEvents` 用 `Listener::ProcessEpollEvents(...) && (UpdateReTxCount, true)` 短路——wakeup 返回 false 时 `UpdateReTxCount` 不被调用
17. **头文件内联 static 局部单例的分支噪音(实测严重)**: `ubsocket_print_stats_mgr.h` 原 `static ALWAYS_INLINE GetPrintStatsMgr()` 内 `static PrintStatsMgr mgr;` 的 guard + 内联构造函数成员初始化异常分支全部记到 `mgr;` 声明行(实测一行 300~400 条 BRDA),且头文件被多个 TU 包含时各自插桩、合并后成倍膨胀——**分支% 被噪音拖到 30% 以下,逻辑分支全绿也上不去**。**修复处方(当前仓库树未应用)**: 把 `GetPrintStatsMgr`/构造/析构**移出到头文件外的 `.cpp`**(如 `statistics/ubsocket_print_stats_mgr.cpp`,GLOB_RECURSE 自动纳入),单 TU 插桩 + 构造函数不再内联到 guard 行,header 分支% 可从 ~30% 跃升到 ~70%。**注意**: 本仓库当前 `ubsocket_print_stats_mgr.h` 仍含内联 static-local 单例(行 45 附近),`statistics/ubsocket_print_stats_mgr.cpp` **并不存在**——陷阱描述的是问题模式与修法,不是已完成的改动;数据源 §5 也不含该 `.cpp` 行。**规律**: 头文件里"函数局部 static + 重量级成员构造"的组合,构造函数的 `(throw)` 异常分支会记到 static 声明行而非构造函数体,欲降噪必须把定义移到 `.cpp`。**UT 侧降噪实测有效(不改源码)**: `GetPrintStatsMgr` 是 `static ALWAYS_INLINE`,在 `-O0` 下仍逐调用点强制内联——**每个 `TEST_F` 体里写一行 `PrintStatsMgr::GetPrintStatsMgr()` 就新增一份 guard + 构造 EH 插桩(约 8~10 条 BRDA)记到 47 行**,新增测试的收益会被新增噪音吃掉甚至倒挂。**实测手法**: 把 fixture 的 `SetUp` 里取一次 `mgr_ = GetPrintStatsMgr()`,测试体一律用成员 `mgr_`,38 个分散调用点收敛为 1 个后,线 47 噪音大幅下降、分支% 显著提升(同陷阱 25 的"单一调用点"原理)。已实测该文件分支覆盖在"新加 5 个真分支用例 + 收敛调用点"后有明显跃升;剩余不可覆盖: 47 行 guard 噪音、`(throw)` 异常边、`snprintf` 负值分支、析构函数分支。彻底根治仍需源码侧移 `.cpp`
18. **`TRACE_*` 宏在测试构建编译为空** — `ubsocket_trace.h` 的 `TRACE_ADD_WRITE`/`TRACE_DRAIN_AND_PRINT`/`TRACE_FLUSH` 等全部包在 `#ifdef UBS_SPLIT_TRACE_ENABLED_COMPILE` 内,测试构建未定义该宏 → 宏体为空、生产代码从不调用 `SplitTrace` 方法 → 头文件分支覆盖率只能靠测试**直接调用方法**补。同理 `ubsocket_get_timeNs_compile()` 展开为常量 0,断言时间戳时**不能** `EXPECT_NE(ts, 0)`
19. **头文件内联类方法的分支归属(`-O0` 下可测)** — 测试构建是 `-O0`(不是 `-fno-inline`),头文件内联方法以外部函数形式落盘 → 其分支归属到头文件行;测试里直接调用 `SplitTrace` 各方法即可把分支记到 `ubsocket_trace.h`。若优化开内联,分支会被记到调用方 `.cpp`,头文件覆盖上不去
20. **`UpdateWriteFirstTrace` 语义** — 后向扫描找**最后一个**匹配 type 的条目,再**前向**回填其后所有 `seq_no==0` 的条目(不回填匹配点之前的、也不看 type)。测试断言前先用实测行为核对,勿假设"回填第一个";回填量/断点用"非 0 seq 遇断"来构造
21. **`AddReadTrace`/`AddWriteTrace` 5 参重载歧义** — detail 版 `(type, fd, uint32_t, uint32_t, uint32_t)` vs time 版 `(type, fd, uint64_t, uint64_t, uint32_t)`。传裸 int 字面量两版都隐式转换 → 歧义编译错。**修复**: detail 用 `u` 后缀字面量(`3u, 100u`),time 用 `static_cast<uint64_t>(...)`
22. **`Logger::SetLogLevel(LEVEL_DEBUG)` 覆盖 `UBS_VLOG_DEBUG` 使能分支** — `Start/Stop/Run` 里的 DEBUG 日志"使能"路径(含 `Logv` 内联的 `len<0` 假分支)只有把日志级别降到 DEBUG 才被覆盖;WARN(3)≥DEBUG(0) 仍使能,不破坏已有 WARN 分支。注意"级别禁用"分支与使能路径互斥,单进程只能二选一
23. **析构 join 分支用局部对象测,勿依赖进程退出** — 覆盖 `~TracePrintThread` 的 `thread_.joinable()==true` 分支,用 `TracePrintThread thread;`(栈上局部、非单例)start 后靠作用域退出触发析构 join,确定性高、无 UB;单例函数局部静态的进程退出析构(线程已 Stop)负责 false 分支,两次都在同一次运行内拿到
24. **单用例 ≤100ms 时间预算** — `TracePrintThread` 测试的 `sleep_for` 是主要耗时。`TEST_RUN_MS` 保持小值(如 10ms)即可让 `Run()` 线程循环 ≥1 次(覆盖 `while(true)` 分支 + 循环内 `DrainAllSockets`),实测单用例 ~15ms,余量充足;线程启动/join 各态无需长 sleep 也能稳定覆盖
25. **`statistics_statsmgr.h` 分支覆盖噪音天花板 + 突破处方**(实测): 该头文件被 `statistics.h`/`ubsocket_print_stats_mgr.h`/`ubsocket_core_types.h` 等大量 TU 包含,`ALWAYS_INLINE` 方法(`OutputAllStats`/`UpdateTraceStats`/`GetInfo` 等)在每个调用点各生成一份插桩拷贝,分支按**调用点(call site)记账**而非按方法。噪音来源: ①`oss <<` 链与 `new` 的 `(throw)` 异常分支(约占全文件 1/3); ②`stat_exporter.cpp` 编译出但永不调用的死拷贝(弱符号 `ProcessStats` 无调用路径,分支永远 `-`); ③`switch(type)` 跳转表跨拷贝合并的 dispatch 边; ④**每新增一个调用内联方法的 `TEST_F` 都会向 BRF 注入整份新拷贝的噪音**——直接堆测试用例收益递减甚至倒挂。**突破处方(实测 40%→52%)**: 把既有/新增用例改写成**单一调用点 + 循环切换分支条件**,让一个调用点在循环内覆盖两条路径(如 `OutputAllStats` 循环内交替 mock `localtime_r` 成功/失败;`UpdateTraceStats` 单调用点循环遍历全部枚举值 + 切换 recorder 空/非空;`GetSocketCLIData` 单调用点循环切换 data 空/非空 + recorder 空/非空 覆盖 `||` 短路全分支)。这使拷贝完全覆盖(+N/N),并把**多个分散调用点合并为一个**(BRF 反而下降)。不可覆盖的剩余: `(throw)` 异常分支、`stat_exporter.o` 死拷贝、生产 TU(connector/data-tx)只调固定类型的单侧拷贝、`UBS_VLOG_ERR` 宏内 `vsnprintf` 负值分支。**彻底解法仍需源码改动**(内联方法移出到 `.cpp`,同陷阱 17 处方)。
26. **mockcpp 无法 mock `malloc`(实测严重 — 无限递归 SIGSEGV)**: mockcpp 用 `JmpOnlyApiHook` **改写目标函数前几条指令**(`changeCode(m_api, ...)` 直接把函数体首个字节替换为跳转)。因此想"先 `dlsym(RTLD_NEXT, "malloc")` 拿真身、mock 内对其他 size 透传"的做法**必然递归崩溃**——mock 装的 `::malloc` 与 `dlsym` 返回的 `malloc` 是同一地址,`MockMalloc` 调 `g_realMalloc` 又跳回 `MockMalloc` → 栈溢出。**结论**: `CLIMessage::AllocateIfNeed` 的 malloc 失败分支(`if (!msg.AllocateIfNeed(totalSize))` 的失败返回路径,statistics.h 各 `Process*Request` 的 `Failed to alloc response memory`)**不可通过 mock 覆盖**,与其配套的 `UBS_VLOG_ERR` 行同理。这些分支计入 BRF 且长期不可达,属噪声(statistics_test 实测)。若要覆盖必须改源码(注入失败点),UT 侧无解
27. **`statistics.h` `UBS_VLOG_*` 宏行的 `('0','3')` 分支是日志内部噪音(实测不可覆盖)**: lcov 报告里各 `UBS_VLOG_ERR/WARN/DEBUG` 行常见一个永远 take=0 的 `('0','3')` 分支——既不是"使能/禁用"侧(两侧都可通过默认 logLevel + `LEVEL_COUNT` 覆盖),也不是 `Logger::Log` 的 `mLogFunc != nullptr` 侧(实测设 `SetExternalLogFunction` 无效),而是 `Logv` 内 `vsnprintf len<0` 之类的不可达边。**别为它加测试**——收益为零,只增加用例噪音。lcorc 的 `excl_br_line = UBS_VLOG_|...` 在本仓 lcov 2.5 下对这些行未生效(`('0','3')` 仍计入 BRF)
28. **错误路径日志"禁用"分支可用单用例批量覆盖**: 把多个错误场景(mock 各 `LibcApi::xxx_ptr` 失败、`RecvCmd/SendCmd` 失败、各 `Process*Request` 发送失败)收敛进一个 `logLevel=LEVEL_COUNT` 的 `TEST_F`,一次 `make coverage` 即可给 ~20 个 `UBS_VLOG_*` 行的"禁用"分支 +N。注意各 mock 调用计数(`g_mockRecvSocketDataCall`/`g_mockSendSocketDataCall`/`g_mockSetsockoptCall`)是**跨场景累计**的,每个场景前必须归零,否则 `FailOnCall` 语义错乱(statistics_test `ErrorPaths_LogDisabled_NoCrash` 实测)
29. **全局 static 模式 latch(`ubsocket_prof_mode_ext`)+ `GlobalSetting` 驱动**(实测,ubsocket_profiling_test): `ubsocket_prof_*` 五函数都按 `ubsocket_prof_mode_ext`(ubsocket_prof.cpp 文件内 static,无 getter)分派到 `Tracer`(fast)或 `TracerExt`(ext)。latch 由**每次** `ubsocket_prof_init` 重读 `GlobalSetting::UBS_PROF_MODE`。**测 ext 分支的 record/combind/reset 前,必须先用 `UBS_PROF_MODE="ext"` 调过 init 把 latch 置 1**,否则 latch 停留在上次 fast,断言落在 fast 实现上(mock `::sched_getcpu` 成死代码,假阳性)。`SetUp` 显式复位 `UBS_PROF_MODE = "fast"` + `TearDown` 调 `ubsocket_prof_uninit()`(latch 归 0),防跨用例污染
30. **ext 模式依赖裸 `::sched_getcpu`**(实测): `ubsocket_prof_tracer_ext.h:75` `RecordExt` 内直接调 `sched_getcpu()` 按 CPU 聚合百分位,**不经 `LibcApi`**。测 ext 模式 record/combind 时 `MOCKER_CPP(::sched_getcpu).stubs().will(invoke(&MockSchedGetCpu))`(static 函数 `int()` 签名精确匹配,返回 `g_mockCpuId`);不 mock 也能跑(glibc 返回真实 cpu 号)但行为不确定,规范应显式 mock 消除假阳性
31. **`ubsocket_prof_combind` 返回 malloc 的 `out_buf` + `ubsocket_prof_enabled` 语义**(实测): combind 成功时 `*out_buf` 由内部 malloc,测试后必须 `free(outBuf)`。`ubsocket_prof_enabled` 在 fast/ext 两种 init 成功路径都置 1——**区分模式靠 `ubsocket_prof_init` 返回值,不能靠该 flag**;init 失败路径 flag 保持 0(可 `EXPECT_EQ(ubsocket_prof_enabled, 0)` 验证失败路径)
32. **`DumpThreadExt::DumpDataExt` 测试需先 `InitExt` 建立 `trace_combiner_`**(实测,ubsocket_prof_tracer_ext_test): `DumpDataExt()`(在 `impl/ubsocket_prof_tracepoint_dumper_ext.cpp`,此文件仅此一函数)内部调 `TracerExt::Instance().CombineExt(oss)`,未 init 时 `trace_combiner_` 为 nullptr → `CombineExt(out)` 返回 0 后走 `trace_combiner_->OutputTraceGroupExt(oss, out)` **空指针崩溃**。测试必须先 `InitExt`(复用 `InitTracer`)建立 combiner。`DumpDataExt` 是 private,成员 `file_name_/dir_created_/dump_file_` 同理,需 `-fno-access-control`(见陷阱 33)。失败分支靠 `MOCKER_CPP(::mkdir).stubs().will(invoke(&MockMkdirFail))`(置 `errno=EACCES` 返回 -1)触发 `CreateDirectoryExt` 首个 `/` 前缀即返回 -1;`WriteDumpDataExt` 返回值 !=0 走 `UBS_VLOG_WARN` + return。日志使能/禁用分支用 `Logger::SetLogLevel(LEVEL_DEBUG/LEVEL_ERR)` 切换,用例内保存/恢复原级别(该 fixture 无日志级别复位),防跨用例污染
33. **轻量 profiling test target 访问私有成员必须显式加 `-fno-access-control`**(实测严重 — 编译报 access control 错误): 全局 `add_compile_options(-fpermissive ...)`(`src/ubsocket/CMakeLists.txt:41`) **不会**降级 C++ 访问控制错误(仅降级部分语义错误),私有成员/方法访问必须靠 test target 自身 `target_compile_options(... PRIVATE -fno-access-control)`。受影响: `TraceCombiner::OutputTracePointCli/OutputTracePointStats` 及 `TraceCombinerExt::OutputTracePointCliExt/OutputTracePointStatsExt` 为 private,其中 `OutputTracePointCli`(非 ext)生产代码无调用路径(死代码,见 `ubsocket_prof_tracepoint_combiner.cpp` 仅 `OutputTraceGroup` 调 `OutputTracePointStats`),只能直测;`TracerExt::CreateAgentExt/agents_/inited_/trace_combiner_/dump_thread_`、`DumpThreadExt::DumpDataExt/file_name_/dir_created_/dump_file_`、`Tracer::tls_group`、`TraceGroup::ref_count_` 同理。`ubsocket_prof_tracer_ext_test`、`ubsocket_prof_tracepoint_combiner_test`、`ubsocket_prof_tracepoint_combiner_ext_test` 三个轻量 target 均已补 `-fno-access-control`
34. **`RotateDumpFileExt` 需 mock `::stat`/`::fork`/`::waitpid` 三件套**(实测,ubsocket_prof_tracer_ext_test): 触发轮转先 mock `::stat` 使 `st_size >= DUMP_FILE_MAX_SIZE_EXT`(且 `st_mtime` 置 0)。`CompressFileExt` 内部 `fork()` 会产生子进程,若真 fork 则子进程 `execlp("gzip", ...)` 污染测试进程 → **必须 mock `::fork`**: 返回 -1 走 fork 失败分支(`CompressFileExt` false → `unlink`),返回父进程 pid(非 0)走 `waitpid` 分支;`::waitpid` mock 里置 `*status` 控制 `WIFEXITED/WEXITSTATUS`——`*status=0` 走 exit 0(压缩成功,不 unlink)、`*status=1<<8` 走非 0(压缩失败 → `unlink`)。`file_name_`/`last_file_path_`/`dump_file_` 均为 private,需 `-fno-access-control`(陷阱 33)
35. **`WriteDumpTitleExt` `::localtime_r` 失败分支用 nullptr mock**(实测): `localtime_r` 返回 nullptr 走 `timeBuf[0]='\0'` + `UBS_VLOG_WARN` 分支,断言 `oss.str()` 仍含 `"timeStamp: "`(空时间戳)。日志禁用分支需 `SetLogLevel(LEVEL_ERR)` 并保存/恢复原级别(该 fixture 无级别复位)。mock 返回指针函数须 `returnValue(static_cast<struct tm *>(nullptr))`(陷阱 8 的 `decltype(nullptr)` 类型不匹配)
36. **`TraceGroup` 私有 `ref_count_` 直测引用计数**(实测,ubsocket_prof_tracepoint_group_test): `MakeRef<TraceGroup>(n)` 创建时 `ref_count_==1`,拷贝 `TraceGroupPtr`(`Ref<TraceGroup>`)增 1、作用域退出减 1、最后一个 ref 释放时析构。断言 `ref_count_` 需 `-fno-access-control`(陷阱 33)。模板智能指针的增/减/析构分支按**调用点**记账,建议单一调用点收敛(陷阱 25 原理)
