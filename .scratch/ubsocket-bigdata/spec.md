# Spec: DoReadOffer get_remote_fields 失败分支资源泄漏修复

> *This spec was generated by AI from the triage of issue 01 (`.scratch/ubsocket-bigdata/issues/01`, Status: ready-for-agent).*
> 领域术语遵循 ubsocket 既有文档(设计 §4-§6、`UBSOCKET-BIGDATA-UT-RESEARCH.ch.md`);ADR 无冲突(`docs/adr/0001-coverage-policy-per-module-80-50-no-cap.md` 不受影响——本修复不改覆盖归属)。

## Problem Statement

当接收路径收到 READ_OFFER,而其中某段的 mempool blob 无法被后端解码(`umq_mempool_info_get_remote_fields` 失败)时,当前行为:释放当前段的 READ 目标 buf、向对端发 UBS_READ_ABORT,随即返回。但:

- 该 offer 此前已入队的 READ 目标 buf(`wr_slots` 中的 pending)没有释放;
- offer RX buf 的所有权已移交给 ctx(RAII 兜底已失效),ctx 被丢弃即该 buf 泄漏;
- 事务 ctx(`new` 出来的 `UbsBigIoCtx`)本身未删除,它持有的 state 引用(`IncreaseRef`)永不归还 → socket state 引用计数永不为零,`CleanupSocketState` 后 state 无法释放;
- 若已设置 peer 超时,`ctx_with_deadline` 快路径计数向上泄漏(无对应的 fetch_sub),sweep 机制将永远访问该 socket。

该失败分支中 ctx 尚未插入 `active_io`,既有回收路径(sweep / CleanupSocketState)扫不到它——泄漏不可被任何机制兜住。对长期运行的服务进程,这类失败累计即永久内存 + 引用泄漏。

## Solution

修复 `DoReadOffer` 的 get_remote_fields 失败分支,使其执行与同函数 alloc 失败分支等价的完整清理序列:

1. 释放当前段的 dest buf;
2. 释放 `wr_slots` 中已入队的全部 pending dest buf;
3. 释放 `offer_rx_buf` 并置 nullptr;
4. 调用 `DeleteIoUctx(ctx)`(单一删除入口:回退 `ctx_with_deadline` 计数 + 释放 state 引用 + 删除 ctx);
5. 发 UBS_READ_ABORT。

wire 语义不变:失败仍以 UBS_READ_ABORT 应答对端;成功路径与其它失败分支不触碰。

## User Stories

1. As a server operator running long-lived connections, I want receive-path failure branches to release every buffer and state reference, so that transient malformed offers do not accumulate into permanent memory/state leaks.
2. As an UBSocket integrator, I want a READ_OFFER whose mempool cannot be decoded to be cleanly aborted, so that the peer is notified and the connection stays consistent.
3. As an UBSocket integrator, I want the abort to be the only wire effect of this failure, so that the offer → ABORT protocol contract is unchanged.
4. As a maintainer, I want this failure branch to mirror the established cleanup sequence of the allocation-failure branch, so that all failure exits of the READ WR build loop have identical resource semantics and are auditable at a glance.
5. As a maintainer, I want `DeleteIoUctx` to remain the single chokepoint for ctx deletion, so that deadline-counter and state-ref accounting cannot diverge between failure branches.
6. As a developer, I want the existing `HandleRxControl_OfferGetRemoteFieldsFail_AbortSent` case to assert the fixed behavior (two frees), so that a regression to the leak fails the build.
7. As a developer, I want a multi-segment mid-failure case, so that already-queued READ dest buffers are asserted freed, not just the current segment's.
8. As a reviewer, I want the fix covered by a test that drives only the public API and asserts observable effects, so that it complies with the repo's mockcpp-only discipline.
9. As a developer, I want socket teardown after such a failure to fully release the state, so that no lingering state or UAF survives `CleanupSocketState`.
10. As a maintainer, I want the triage verification and this spec recorded in the tracker, so that the fix decision is durable and re-traceable.

## Implementation Decisions

- **修复对象**: `UbsBigdata::DoReadOffer` 的 get_remote_fields 失败分支(UbsBigdata 接收路径,由 `HandleRxControl(READ_OFFER)` 驱动;内部函数与 `UbsBigIoCtx` 均在匿名 namespace,只能经公共 API 间接驱动——research doc §4.1)。
- **清理序列**: 完整镜像同函数 alloc 失败分支——释放当前 dest → 释放全部 `wr_slots` pending → 释放 `offer_rx_buf` 并置 nullptr → `DeleteIoUctx(ctx)` → `SendSimpleCtrl(UBS_READ_ABORT)`。
- **`DeleteIoUctx` 是唯一删除入口**: 它统一回退 `ctx_with_deadline`(若 ctx 带 deadline)并释放 state 引用(`state->DecreaseRef()`);修复必须复用它,不得内联部分记账,防止各失败分支记账分叉。
- **顺序无依赖风险**: `DoReadOffer` 内的 `BigdataStateRef` RAII 在函数全程保活 state,先清理再发 ABORT 安全。
- **无接口变更**: 不新增/修改任何函数签名、不引入新公共 API;无 wire/协议变更。
- **测试侧**: 更新既有 `HandleRxControl_OfferGetRemoteFieldsFail_AbortSent`(free 计数 1→2,移除"已知缺陷"注释);新增一个多段中途失败用例,断言已入队段全部释放。

## Testing Decisions

- **好的测试判据**: 只断言外部可观察行为——`umq_post` 调用次数与内容、`umq_buf_free` 计数、socket 状态——不检查内部结构。
- **接缝**: 既有公共 API 接缝——真实 `UmqSocket` 注册进 `ArraySet<Socket>`,UMQ API 边界经 `MOCKER_CPP(::umq_*)` 全 mock,用既有 fake 挂载体系(`PrepareReceiveSocket`/`MountReceiveMocks` 等 helper)驱动 `UbsBigdata::HandleRxControl`。这是唯一可行接缝:内部函数与 ctx 类型在匿名 namespace,测试 TU 无法引用;直构方案已在批 2 定案否决(全链定案)。**无需新接缝**。
- **被测模块**: `src/ubsocket` core 的 bigdata 路径,经 `ubsocket_bigdata_test` target。
- **先例**:
  - `HandleRxControl_OfferGetRemoteFieldsFail_AbortSent`(既有,本修复的锚定用例,断言待更新);

  - `HandleRxControl_OfferImportFail_AbortSent`(同类失败分支的 ABORT + 释放语义先例)。
