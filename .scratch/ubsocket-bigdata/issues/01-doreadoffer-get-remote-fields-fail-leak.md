## Agent Brief

**Category:** bug
**Summary:** DoReadOffer 的 get_remote_fields 失败分支泄漏 ctx / offer RX buf / state 引用

**Current behavior:**
`DoReadOffer`(UbsBigdata 接收路径,由 `HandleRxControl(READ_OFFER)` 驱动,匿名 namespace 内部函数,只能经公共 API 驱动)在构造 READ WR 链时,若某段的 `umq_mempool_info_get_remote_fields` 调用失败,当前分支仅释放当前段的 dest buf 并发 UBS_READ_ABORT 即 return,导致:
- 已入 `ctx->wr_slots` 的先前段 dest buf 泄漏
- `ctx->offer_rx_buf` 泄漏(所有权已在 ctx 接管后移出 RAII 兜底)
- `ctx`(new'ed `UbsBigIoCtx`)与其持有的 state 引用(`state->IncreaseRef()`)泄漏 — state 引用计数永不为零,CleanupSocketState 后 state 无法释放
- 设置了 peer 超时时 `ctx_with_deadline` 计数向上泄漏(`DeleteIoUctx` 是唯一回退点)
该失败分支中 ctx 尚未插入 `active_io`,既有回收路径(CleanupSocketState/sweep)扫不到它。

**Desired behavior:**
get_remote_fields 失败分支执行与同函数 alloc 失败分支等价的完整清理序列:释放当前段 dest + 释放 wr_slots 中已入队的所有 pending dest + 释放 `ctx->offer_rx_buf`(置 nullptr)+ `DeleteIoUctx(ctx)`(释放 ctx、回退 ctx_with_deadline、释放 state 引用)+ 发 UBS_READ_ABORT。`state` 由 DoReadOffer 内 `BigdataStateRef` 保活,先清理再发 ABORT 无顺序风险。

**Key interfaces:**
- `UbsBigdata::DoReadOffer` — 失败分支补齐清理;镜像同函数 alloc 失败分支的序列(释放 buf 链 → `DeleteIoUctx` → `SendSimpleCtrl(UBS_READ_ABORT)`)
- `DeleteIoUctx(ctx)` — 统一 ctx 删除入口(ctx 释放 + ctx_with_deadline 回退 + `state->DecreaseRef`),必须调用
- `HandleRxControl_OfferGetRemoteFieldsFail_AbortSent` 用例 — 断言从 `free_count==1` 更新为 `free_count==2`(dest + offer,单段),移除"已知缺陷"注释;UBS_READ_ABORT 仍须发出(post 计数 1),socket 不置 CLOSE

**Acceptance criteria:**
- [ ] get_remote_fields 失败(单段 offer): ABORT 发出(1 个 post),`free_count==2`(dest + offer)
- [ ] 多段 offer 中途失败: 已入队段全部释放(free 计数 = 已入队段数 + 当前 dest + offer)
- [ ] 无泄漏: 用例结束后 TearDown/CleanupSocketState 正常收尾,无 UAF、无未释放 state 引用(可经 valgrind 或引用计数断言验证)
- [ ] `ubsocket_bigdata_test` target 全绿;全量 ctest 通过(60/60)
- [ ] 覆盖率不降(该分支已被用例覆盖,修复不改覆盖归属);边界清单无新增判定点

**Out of scope:**
- 其它 DoReadOffer 失败分支(alloc 失败、import 失败、post 失败等已有完整清理,不动)
- 并发 destroying 守卫路径(单线程测试不可达的既有豁免,见 core.md 豁免登记)
- issue 02(SweepExpiredCtxs active_io 残留,已在 bigdata_bufix 分支修复,与本 issue 无耦合)
